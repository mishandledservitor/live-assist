# Research: Meet speaker names

**Feature**: `002-meet-speaker-names` | **Date**: 2026-10-08 (revised the same day for the single mixed stream — design decisions 28–30, constitution v1.1.0)

Sources checked on 2026-10-08. Google publishes no contract for Meet's page, so every selector below comes from open-source code that reads the live Meet page, and from those projects' own saved fixtures. Each source's last change date is given so staleness is visible:

- TranscripTonic (`vivek-nexus/transcriptonic`, `extension/content-scripts/google-meet/{config,index,utils}.js`, config last changed 2026-07-18): clicks the captions button found by the Material Symbols ligature `closed_caption_off` inside `.google-symbols`; captions region `div[role="region"][tabindex="0"]`; in-call detection by the `call_end` ligature; name element = previous sibling of the text element inside a caption block; notes that Meet edits earlier blocks to correct them and that the region exists whether captions are on or off.

- AWS `amazon-transcribe-live-meeting-assistant` (`lma-browser-extension-stack/public/content_scripts/providers/meet.js`, last changed 2026-04-16): mute via MutationObserver on `button[data-mute-button]`'s `data-is-muted` attribute; title `div[data-meeting-title]`; tiles `div[data-participant-id]`.

Where a fact could not be confirmed from two independent sources it is marked **unverified** and a task checks it against a real snapshot (tasks Phase 7, "Real Meet snapshots").

## R1. Locating things on the Meet page

**Decision**: every DOM lookup goes through one module of *locators* (`src/platforms/meet/locators.ts`, pure functions over a `Document`/`Element`). Each locator tries tiers in a fixed order and reports which tier matched:

1. **Semantic**: roles, `aria-*`, `data-*` attributes Meet uses for behaviour (`data-is-muted`, `data-mute-button`, `data-meeting-title`, `data-participant-id`, `aria-pressed`, `role="region"`).
2. **Language-independent icon**: Material Symbols ligature text (`closed_caption`, `closed_caption_off`, `mic`, `mic_off`, `call_end`) inside an icon element (`.google-symbols`, `i`, `[aria-hidden="true"]`) — identical in every UI language.
3. **English `aria-label` text** (`/captions/i`, `/microphone/i`, `"Captions"`, `"Call controls"`) — works only with an English Meet UI, so it is never the only route.
4. **Generated class names** (`.nMcdL`, `.NWpY1d`, `.ygicle`) — last resort.

| Thing | Tier 1 | Tier 2 | Tier 3 | Tier 4 |
|-------|--------|--------|--------|--------|
| In a call (not lobby) | — | a button whose icon is `call_end` | `[role="region"][aria-label="Call controls"]` | — |
| Captions button | `button[aria-pressed]` that contains the icon below | icon `closed_caption` / `closed_caption_off` | `button[aria-label*="caption" i]` | — |
| Captions on? | `aria-pressed="true"` (absent on the real page, R13) | icon `closed_caption` while on (seen, R13); the off icon is still **unverified**, so the label is read first since R13 | label starts "Turn off captions" (seen, R13) | — |
| Captions region | `[role="region"]` whose children hold caption turns and at most 3 other children, never a "notification" region (revised R13) | — | `aria-label="Captions"` (seen) | `div[role="region"][tabindex="0"]` with few children (seen) |
| Caption item (one turn) | region child whose first child (header) holds an avatar `img[data-iml]` or `img[src*="googleusercontent.com"]` and the name span (seen, R13) | — | — | `.nMcdL` (seen) |
| Speaker name | first `span` in the item's header (the element before the text) | — | — | `.NWpY1d` |
| Mic button | `button[data-is-muted]` with `data-mute-button` (absent on the real page), or a `button[data-is-muted]` whose icon is `mic`/`mic_off` or whose label contains "microphone"; never a camera button, which also carries `data-is-muted` (R13) | icon `mic` / `mic_off` (**unverified**) | `aria-label` contains "microphone" (seen: "Turn off microphone") | — |
| Muted? | `data-is-muted="true"/"false"` | icon `mic_off` vs `mic` | "Turn on microphone" = muted | — |
| Title | `[data-meeting-title]` attribute | — | `document.title` minus `Meet - ` / `Meet – ` | — |
| Meeting code | URL path `/^\/(?:meet\/)?([a-z]{3}-[a-z]{4}-[a-z]{3})/` (the `/meet/` prefix since October 2026, decision 101) | — | — | — |

A locator that only matches at tier 3 or 4 still works, but the content script logs the tier (names only, no text) so a drift is visible before it breaks. Participants are **not** read: no requirement needs a participant list (spec edge case: names are picked up as captions appear; Principle VI).

**Rationale**: Constitution V and III — the page changes without notice; one module, tested against saved snapshots, is the only place to fix. Language-independent tiers matter because the user's Meet UI may be Greek.

**Alternatives considered**: class names first (what most extensions do; the sources agree they churn); Meet's internal `script.ds:*` data blobs (fragile, undocumented, reads more than needed); the active-speaker tile highlight as a name source (LMA does this) — rejected for v1 because it adds a second, noisier name source (Principle VI); revisit only if captions prove unusable.

## R2. Where the Meet adapter runs

**Decision**: a **manifest-declared content script** on `https://meet.google.com/*` (`src/entrypoints/meet.content/`), idle until the service worker attaches it to a running meeting. It holds all DOM code (locators, caption observer, mute observer, captions control). The offscreen document's `MeetingRuntime` sees it through `PlatformAdapter` via a `BridgedMeetAdapter` in core (`src/core/platform/meet-bridge-adapter.ts`), which talks to the content script over an injected `BridgePort` (contracts/meet-bridge.md).

**Rationale**: the runtime lives in the offscreen document (001 R5), which cannot touch the Meet tab's DOM; the 001 contract already planned "a content script … over a message bridge". A declared content script is re-injected automatically when the Meet page reloads, so a reload mid-meeting reconnects by itself.

**Alternatives considered**: programmatic injection with `scripting.executeScript` under `activeTab` (no host match in the manifest) — rejected because the `activeTab` grant ends when the tab reloads, so a reload would lose names and mute following for the rest of the meeting. The declared match adds `meet.google.com` to the extension's site access; no network destination changes (Principle I is about where audio and text go, and the content script sends nothing anywhere but the extension). The privacy guard test (001 T089) asserts "no content scripts" and is updated deliberately to "exactly one content script, matching only `https://meet.google.com/*`".

## R3. Bridge transport and attach handshake

**Decision**:
- On Start, after the offscreen document has begun the meeting, the service worker sends `meet/attach { meetingId }` to the captured tab (`chrome.tabs.sendMessage`). The content script answers by opening `chrome.runtime.connect({ name: 'platform:meet' })`. The offscreen host accepts ports with that name and hands them to the runtime's `BridgedMeetAdapter`.
- After a page reload the new content script sends `meet/ready`; the service worker replies `{ attach: true, meetingId }` if that tab is the running meeting's tab, and the script connects again. The adapter accepts the newer port and drops the old one.
- If no port arrives within `ATTACH_TIMEOUT_MS` (5 s) of Start: speaker names and mute following are unavailable with the reason "Couldn't connect to the Meet page — reload the Meet tab".
- **Verified 2026-10-08** (tasks T005, `tests/e2e/meet-bridge.spec.ts`): the offscreen document receives `runtime.onConnect` for the `platform:meet` port a content script opens with `chrome.runtime.connect`, and the first message on it. No service-worker relay is needed. One e2e-only finding: the service worker sees the tab's URL only through the activeTab grant of the toolbar click (content-script `matches` do not reveal it), so e2e builds, which cannot click the icon, add the `tabs` permission (`wxt.config.ts`, e2e mode only).

**Rationale**: no polling, works after reloads, and the service worker stays out of the hot path (caption events at up to ~10/s).

## R4. Turning captions on, hiding them, restoring them

**Decision**:
- `enable()` (called by the runtime once the transcription stream is active): wait until in call (lobby → status "Join the call to get speaker names", keep waiting, no timeout while in the lobby). Once in call, find the captions button within `CAPTIONS_BUTTON_TIMEOUT_MS` (4 s); read its state; remember `wasOn`; if off, `click()` it and wait up to `CAPTIONS_ON_TIMEOUT_MS` (4 s) for it to report on. Independently, `BridgedMeetAdapter` enforces `NAMES_DEADLINE_MS` (9 s from Start): unless captions are `on` or the page reported the lobby by then, it reports `unavailable` with the most specific reason it has — so SC-003's 10 s holds even when the page connects late. Then find the region and start observing.
- **Hide**: tag the region's outer container with `data-live-assist-hidden` and inject one stylesheet: `opacity: 0 !important; pointer-events: none !important;`. The nodes stay rendered so Meet keeps updating them. Meet may still reserve space for the captions band; whether a collapse rule (`max-height: 0; overflow: hidden`) keeps captions updating is checked in the real-meeting check, and the rule is one constant (`HIDE_CSS`) to change.
- **Revised by the real call 2026-10-09 (tasks T124–T127)**: the invisible band still took up a large strip above the control bar (with the captions' language / "Live captions" row). Now the region keeps its `opacity: 0` tag and, in addition, the **captions band** (`captionsBand` in `locators.ts`) is tagged `data-live-assist-collapsed`: walking up from the region at most 3 levels, the highest ancestor that holds no other `[role=region|main|dialog|alertdialog|toolbar]`, no `[data-participant-id]`, no `video`, no leave or captions button and is not `body`; the region itself if none qualifies (so a parent shared with the notifications region, R13, is never collapsed). On the R13 structure that is `div.iOzk7[jsname=dsyhDe]`. The collapse rule in `HIDE_CSS` is `height`/`min-height`/`max-height: 0`, vertical padding, margin and border 0, `overflow: hidden`, `flex: 0 0 0`, `pointer-events: none`, all `!important`. It never uses `display: none` or `visibility: hidden`: the nodes stay in the layout tree, Meet's renderer keeps writing caption turns into them, and the `MutationObserver` on the region sees every change (styles do not affect mutation delivery). The e2e test checks that the band's box is 0 px high, the control bar moves up by the band's height, names keep arriving and Stop restores the original box. Whether the reserved space belongs to the band or to a sibling Meet sizes itself is confirmed in the next real call; a band re-rendered by Meet is re-tagged on the next poll.
- `restore()` (Stop, meeting end, tab close is a no-op): remove the stylesheet and both attributes; if `wasOn` was false and captions are still on, click the button once to turn them off.
- If the user turns captions off during transcription (button goes off without our click): do not fight — state `off-by-user`, reason "Captions were turned off", names degrade (FR-010). If the user turns them back on, reading resumes. Restore leaves the user's choice alone.
- Untrusted `click()` on Meet buttons works in TranscripTonic and the bots above; the keyboard shortcut `c` is not used (synthetic key events are untrusted and may be ignored).
- Meet captions are per-user (design decision 5); turning them on does not notify others — SC-006 is confirmed in the real-meeting check.

**Failure reasons** (shown in the status area): "Couldn't turn on Meet captions" (button missing or never turns on), "Meet's captions can't be read — the page may have changed" (on, but no region/items found within 10 s of speech), "Captions were turned off", "Join the call to get speaker names", "Couldn't connect to the Meet page — reload the Meet tab".

## R5. Caption turns — names and timing only, never text

**Amended 2026-10-12 (feature 013, design decision 63)**: the decision below, "the content script never reads caption text", is reversed for one purpose. The content script now also reads each changed turn's text and sends it in a separate message, `meet/caption-text`, to be stored locally with the meeting and downloaded with the transcript. Everything this section says about activity is unchanged: activity events carry no text, are throttled as before, and are the only input to naming. How the text is read, bounded and validated: `specs/013-captions-download/research.md` R1–R3 and `contracts/captions-capture.md`.

**Decision**: the content script never reads caption text. It watches the region with a `MutationObserver` (`childList`, `characterData`, `subtree`) and, for each mutation, finds the caption item it belongs to:
- A new item → a new **turn**: `turnKey` (a counter kept in a `WeakMap<Element, string>`), `speakerName` (from the name element, whitespace-normalised), `self` hint.
- Any later mutation inside an item → an activity event for that turn with `observedAt = Date.now()`.
- Corrections Meet makes to older items (TranscripTonic) are ignored: an item stops producing activity once a newer item exists **for the same speaker**, or after `TURN_CLOSE_MS` (4 s, matches sanand0's settle) without change.
- Events sent over the bridge: `{ turnKey, speakerName, self, observedAt }`, throttled to one per turn per 250 ms (the last one in each window is always sent, so the turn's end time is exact to 250 ms).
- **Self hint**: `self = true` when the name equals Meet's self label. English Meet shows "You" (sanand0 fixture). Other UI languages use a translated word; the adapter compares against a small table (`You`, `Εσύ`, plus any label found on the self tile — **unverified**; "You" seen on the real English page (R13), the Greek word still awaits the Greek-UI snapshot, T068), else `null`. With one mixed stream the self hint is how the user's lines get the user's name (decision 29). An unrecognised self word is not dropped: it names lines as Meet shows it (e.g. a caption name "Εσύ"), which is still what the captions support; the user renames it once and the rename is remembered (R9). No local voice-activity check is used — the user chose captions only (decision 29).

**Revised by the retest 2026-10-08 (tasks T096–T097)**: the rule "an item stops producing activity … after `TURN_CLOSE_MS` (4 s) without change" also closed the item a speaker was still being captioned in. Meet keeps writing an ongoing turn into the same item through pauses, rewrites and older lines dropping off, so after the first pause of 4 s or more the rest of the turn produced no activity: the watchdog degraded names while captions visibly updated (finding 2), and the turn's later lines had no caption turn to be named from (finding 1). Now the newest item never closes; older items still close after `TURN_CLOSE_MS`, and an older item of the same speaker is still ignored. Also fixed: a new item counts as a new turn only when it is appended after the last known item and no known item was removed in the same batch, so a re-render (Meet re-creating item nodes) no longer announces every turn on the page at once, which looked like everyone talking together; the observer keeps its region while it still holds turns, and among regions holding turns the captions region prefers the one labelled "Captions" or focusable, so a side panel whose rows look like turns (a People panel, structure assumed) is neither observed nor hidden. The real page's behaviour is still to be confirmed by the trace (T105).

Core's `CaptionTurnTracker` turns events into `CaptionTurn { turnKey, speakerName, self, firstSeenMs, lastSeenMs }` in meeting time (`observedAt − meeting.startedAt`; content script and offscreen document share the machine clock).

**Rationale**: FR-004 says only name and timing are used; not reading text at all is the strongest form of that and keeps caption text out of every message and log.

## R6. Aligning caption turns with transcript segments

**Inputs**: a segment of the single mixed stream (`startMs`, `endMs`, `words[]` meeting-relative; `timing: 'words' | 'estimated'`) and the caption turns — everyone's, the user's own included (design decision 29). There is no mic-vs-tab distinction any more (decision 28).

**Timing model**: Meet shows a caption shortly *after* the words are spoken and keeps editing it until shortly after they end. The mixed stream carries remote audio at about the time the user hears it and the user's own voice at the time it is spoken; captions of both arrive after a similar round trip to Meet's servers. So a turn's spoken window is estimated as `[firstSeenMs − LEAD_MS, lastSeenMs + TAIL_MS]` with `LEAD_MS = 1500` and `TAIL_MS = 500` (tolerates caption lag of "a few seconds", FR-005). The user's own turns may lag their audio differently from remote turns; the real alignment trace (R11) measures both, and the window becomes per-kind only if the trace shows it is needed.

**Decision — confidence rules** (`src/core/speakers/attribution.ts`, pure):

1. **Candidates**: every caption turn. A turn with `self === true` is the speaker `self`; any other turn is the speaker `caption:<name>`.
2. **Word attribution**: each word (or, for `estimated` timing, the whole segment as one span) is attributed to the candidate speakers whose windows overlap it; a word overlapped by *k* different speakers gives 1/*k* of its duration to each (ambiguity counts against everyone).
3. **Coverage** = attributed duration ÷ total word duration. **Share** of a speaker = their duration ÷ *covered* word duration. (Revised 2026-10-08 by tasks T033: measured against total word duration, a share ≥ 0.8 implied coverage ≥ 0.8, which made `MIN_COVERAGE` dead and left a single speaker unnamed under a 3 s caption lag, the `caption-lag-3s` timeline. Constants unchanged.)
4. **Named (confirmed, `labelSource: 'caption'`)** only if coverage ≥ `MIN_COVERAGE` (0.6) **and** the top speaker's share ≥ `DOMINANCE` (0.8). For `estimated` timing: exactly one candidate speaker overlaps and coverage ≥ 0.8. If the top speaker is `self`, the label is the user's name from settings (meeting snapshot), with `captionName` = Meet's self word.
5. **Otherwise "Others"** (`labelSource: 'fallback'`) — overlapping speech without a clear winner (the user and a remote participant talking at once included; US1-5), no caption at all, or too little coverage. Never the "most likely" name. Without captions every line is "Others", the user's included (constitution IV, v1.1.0).
6. Same display name used by two participants: both are one speaker key (spec edge case); the user splits them with line overrides.

The 60% / 80% thresholds are kept: nothing in the move to one stream argues for different values, and they are validated by the fixtures and the real trace below.

**Pending and settling** (FR-009): a segment is stored at once as "Others" (fallback), with `attribution: 'pending'` in memory, and shown as "…" while names are active (real trace 2026-10-08, below). It is resolved when caption knowledge for its window is settled: at meeting time `endMs + SETTLE_MS` (3 s; 6 s since the real trace) — captions for it have appeared and been edited by then. If a later caption event still changes the outcome, the segment is re-resolved until `endMs + RESOLVE_DEADLINE_MS` (10 s), after which it is final. Every change is stored (segment `put`) before it is broadcast (`live/segment-updated`), keeping 001's write-before-show rule.

**Watchdog** (US2-2, SC-003): when captions are `on` but no caption activity has arrived for `NO_CAPTIONS_MS` (8 s, inside SC-003's 10 s) while the stream shows speech (partials or segments on ≥ 3 distinct seconds in that window), speaker names go `degraded` — "No captions seen for a while — new lines are labelled Others" — and recover on the next caption activity (US2-3). The user talking while muted cannot trigger it: muted mic audio is silenced before mixing, so there is no speech in the stream.

**Tuning**: all constants live in one exported object, validated by the synthetic timeline fixtures (`tests/fixtures/meet/timelines/*.json`, built in tasks) and then by the user's real **alignment trace** (R11). SC-001 (≥ 90% correct on clear turn-taking) and SC-002 (0 wrong confirmed names) are scored by one fixture-suite test that reports both numbers.

**Retest 2026-10-08 (tasks T098–T099)**: five timeline fixtures model what the real call showed — `long-monologue-pauses` (one item through pauses of 5–7 s), `rewritten-items` (Meet rewriting the previous item for ~1.5 s after the next speaker starts), `dropped-older-text` (a 40 s turn whose older lines drop off, with a 4.5 s stall in Meet's updates), `monologue-caption-lag-2s` (lags of 2–2.5 s) and `uncaptioned-gap` (shared-video audio, never captioned, between two parts of the presenter's turn in the same item). A second suite (`tests/unit/platforms/meet/page-timelines.test.ts`) replays every fixture as page changes on the real-structure snapshot through the real caption observer, so the observer and the rules are scored together. Changes, each driven by a fixture:
- A turn's windows come from its **bursts** of activity: a quiet spell longer than `ACTIVITY_GAP_MS` (5 s, above the 4.5 s stall) splits it. With the observer fixed but first-to-last windows, `uncaptioned-gap` named the video audio as the presenter (2 wrong confirmed names); with bursts it is "Others".
- Windows shifted for caption lag: `LEAD_MS` 1500 → 2000 and `TAIL_MS` 500 → −500 (the last change of a burst comes after the last word, so the window now ends half a second before it). With the old values the first line after each handover lost dominance to the previous speaker's late changes (`rewritten-items`, `monologue-caption-lag-2s`: shares 0.68–0.78). A sweep of `LEAD_MS` 1500–3000 × `TAIL_MS` 500 to −1500 over all 14 fixtures: `TAIL_MS` −500 with `LEAD_MS` 1500 or 2000 names every line with 0 wrong confirmed names; 0 and −1000 lose 2–5 lines; `LEAD_MS` ≥ 2500 with `TAIL_MS` ≤ −1000 gives wrong confirmed names. 2000 was chosen over 1500 because it loses fewer lines either side of −500. `MIN_COVERAGE` and `DOMINANCE` unchanged.
- Named-line rate on the page replay (lines whose expected label is a name): before (old observer, old windows) 45/61 = 73.8 % overall and 21/37 on the five retest fixtures, 0 wrong confirmed names; after 61/61 and 37/37, 0 wrong confirmed names. The fixtures are synthetic and the constants were tuned on them, so these numbers say the rules fit the behaviour described, not that a real call will match; the real trace (T105, T070/T071) is the check.

**Real trace 2026-10-08 (tasks T106–T113)**: the first real alignment trace (`tests/fixtures/meet/traces/real-2026-10-08-trace.json`; solo call with a phone as the second participant, 5½ minutes, 24 lines, 3 caption turns) checked the synthetic tuning.
- The trace itself was broken: every `why` read `no-captions`, coverage 0. `AlignmentTraceRecorder.begin()` never ran, because the offscreen document switched the recorder on after a dynamic import that resolved after `createMeeting`; captions stayed epoch ms while segments were meeting-relative. Format-1 traces are converted with the start given by hand (`spike:meet-trace --origin`). For this trace the start was fitted against the live labels: 1791473933400, and offsets 500–700 ms either side give the same labels on all 24 lines.
- With the start applied, the rules reproduce the live labels except seg-18 (03:27, a clear 6-word line of the user's), which stays "Others": the user's caption activity paused for 5,406 ms inside the turn, above `ACTIVITY_GAP_MS` (5000), so the turn split and the line fell between bursts. Sweep of `ACTIVITY_GAP_MS` on the real trace: 4500 → 17/19 named (seg-22 lost too); 5000 → 18/19; 5410–5700 → 19/19 with all 5 "Others" lines kept; ≥ 5800 → seg-17 (03:21, a one-word filler with no caption activity of its own, inside a 5,772 ms pause of the user's captions) is named as the user. **`ACTIVITY_GAP_MS` 5000 → 5500**: inside the window [5406, 5772), with the 4.5 s stall of `dropped-older-text` still below it. With `SETTLE_MS` 3000 those lines first showed "Others" and then changed. **`SETTLE_MS` 3000 → 6000**, and the line shows a neutral "…" until then (design decision 37, FR-026), so the first label a user sees on the real trace is the final one. `RESOLVE_DEADLINE_MS` stays 10000.
- Named lines (expected name): real trace 18/19 → 19/19; all timeline fixtures plus the real one, 0 wrong confirmed names before and after.

**Real call 2026-10-09 — splitting a line at a speaker change (FR-027, design decision 43)**: a 5+-person call put another participant's interjection inside a long line and named the whole line after the main speaker (share above 0.8). One segment, one label is the defect; the dominance rule cannot see a short run of someone else's words.

*Word placement model.* Caption bursts (as above) are read on the speech clock with the lag left uncertain: a burst with first change `f` and last change `l` holds speech in `[f − L, l + TAIL_MS]` for some lag `L` between `LAG_MIN_MS` and `LAG_MAX_MS`. At a speech time `t` and lag `L`, the candidate bursts are those whose window holds `t`; the newest burst (latest `f`) wins over an older one of another speaker unless the older one is still changing more than `REWRITE_MS` after the newer one started (then both are talking: overlap). A word is **placed** with speaker X when, at its start, middle and end and for `L` at `LAG_MIN_MS`, the midpoint, `LEAD_MS` and `LAG_MAX_MS`, the winners are X or nobody, and X at least once. A word whose winners differ across those samples is **contested**; one with nobody at every sample is **uncaptioned**.

*Runs.* Placed words of one speaker, with the uncaptioned words between them, form a run. Contested or uncaptioned words between runs of different speakers, and contested words between two runs of the same speaker (someone else's caption started inside that speaker's speech: an interjection or overlap), form an "Others" run. Words before the first run or after the last join that run (the existing lag tolerance at a line's edges). Each named run is then checked by the existing rules (`attribute`, coverage ≥ 0.6 and dominance ≥ 0.8 on its own words); a run that fails is "Others". Adjacent runs with the same result merge. A line with one run is labelled exactly as before, so single-speaker lines cannot change.

*Constants.* `LAG_MIN_MS` = 400: on the three real traces the first caption change of a burst came 578–2,725 ms after the first word it captioned (13 bursts), so 400 keeps a margin below the shortest lag seen; a smaller value only makes more words contested (more "Others", never a wrong name). `LAG_MAX_MS` = 3000, above `LEAD_MS` (which still sets the whole-line windows): with 2000 the `monologue-caption-lag-2s` fixture (lags of 2–2.5 s) placed a new speaker's first word with the previous speaker and split a clear line wrongly (1 word under the wrong name); at 3000 that line stays whole, and the real traces show lags up to 2,725 ms. A longer maximum only makes more words contested. Its cost: an interjection shorter than about 3 s cannot be placed, so its words become "Others" rather than the interjector's name. `REWRITE_MS` = 1500: the `rewritten-items` fixture models Meet rewriting the previous item for up to about 1 s after the next speaker's item starts.

*Live behaviour.* The attributor resolves every line through the runs (`speakerRuns`); more than one run splits the line at settle (or at a later resolution before the deadline, or at meeting end). Pieces stay pending until the original's deadline; a named piece is re-resolved on later captions, but a piece split off as "Others" is never re-resolved: alone, its words lose the neighbouring context that made them unplaceable, and the whole-line rule could then give them a neighbour's name. A line with an override is never split.

*Results (T117, `timelines.test.ts`).* Per word, against the fixtures' truth (`spokenBy`, or the expected label): words shown under a wrong name 12 → 0 across the suite (interjection-in-long-turn 4 → 0, overlap-mid-line 7 → 0, short-interjection 1 → 0). Every one of the 15 fixtures from before keeps every named word (1,108 named words before and after, real 2026-10-08 timeline 284/284) and every expected line label; SC-001 100 % (74/74 pieces), SC-002 0 wrong confirmed names. The new fixtures trade named words for safety where the whole-line rule was wrong: interjection-in-long-turn 59/63 → 54/63, short-interjection 43/44 → 37/44, overlap-mid-line 17/17 → 12/17 (the "before" counts include words named correctly only because the whole line took the main speaker's name); rapid-back-and-forth 0/26 → 7/26. Real traces of 2026-10-09 (no per-word truth; checked against their own captions): words named where only another speaker's caption windows could hold them 0 → 0 (0929, 0931) and 12 → 0 (0945); named words 167 → 167, 6 → 15 and 1,035 → 1,593 of 1,930; the 0945 trace's 40 lines become 108 (18 lines split). The real interjection was about 2 s, below the placement band, so it now shows as an "Others" line between the main speaker's lines rather than under the interjector's name.

*Alternatives considered*: sub-lines inside one stored segment (one record, several labels) — rejected: the panel, renames, overrides, 003's context and citations and 004's export would all need to learn sub-lines; ordinary segments need none of that. Assigning contested words to the nearest run — rejected: it is exactly "borrowing a neighbour's name". Splitting only by a shorter silence threshold — not enough: on the real 2026-10-09 traces speakers handed over with 40–420 ms between words, below any usable threshold, and the busy 0945 call produced 35 s lines ended by the service's ~36 s auto-commit, not by silence (001 research R3).

**Pending placeholder** (design decision 37, FR-026): a segment stored while names are active (Meet, captions on, watchdog not degraded) carries `labelPending: true`; its stored label is still "Others" (`fallback`), so anything reading the record without the flag sees the safe fallback. The attributor clears the flag on the first resolution at `endMs + SETTLE_MS` (stored, then broadcast, even if the label did not change) and on meeting end. `displayLabel` returns the placeholder only for a pending segment without an override; `normaliseSegment` drops the flag on read, so a crashed meeting's lines show "Others" in history.

**Alternatives considered**:
- Local voice-activity detection on the separately captured mic to recognise the user's lines without captions — rejected by the user in favour of captions only (decision 29).
- Splitting a segment at a speaker change using word times — more names in quick exchanges, but the spec labels such segments "Others", and a split line is a new kind of transcript edit; deferred. **Superseded by the real call 2026-10-09** (above): splitting is now done.
- Adaptive lag estimation (median offset between turn start and first word) — not needed until a real trace shows the fixed window misses; the trace task measures the offset distribution so it can be added with data.
- Nearest-turn assignment with no dominance rule — violates Principle II (a guess shown as a name).

## R7. Reading Meet's mute state

**Decision**: the content script locates the mic button (R1) and observes its `data-is-muted` attribute (and the button being replaced — Meet re-renders the control bar — via a `childList` observer on the controls region, re-locating on change). Reading: `true` / `false`; `null` when no mic button can be found. Each change is sent as `{ muted, observedAt }`; the current value is also sent on attach. In the lobby the pre-join mic toggle carries the same attribute, so the gate is already right when the user joins.

Push-to-talk (holding space while muted) flips the same attribute — **unverified**, in the manual check (US3 step 6).

## R8. The mute gate — what never leaves the machine

**Decision** (design decisions 28 and 30, constitution I v1.1.0): the mic's contribution is **silenced before the mixer, and so before any replay buffer**. 001 (being reworked for one mixed stream) captures tab and mic separately, mixes them into one mono stream for one ElevenLabs session, and exposes a gate on the mic input in front of the mixer. 002's `MuteGate` (`src/core/session/mute-gate.ts`) drives that gate from Meet's mute readings: while muted, mic frames are replaced by silent frames of the same length before mixing; tab audio is untouched. Because the gate sits in front of the mixer, the mixed frames held in 001's reconnect replay buffer never contain muted mic audio, so nothing can be sent on replay (the design-decisions carry-forward note).

Details:
- **Guard hold**: both inputs are held `MUTE_GUARD_MS` (500 ms) before mixing, delayed equally so they stay in sync. A mute reading stamped `observedAt` silences every mic frame still in the hold whose audio ends after `observedAt − MUTE_DETECT_SLACK_MS` (150 ms). This covers the detection path (Meet's button change → observer → port → offscreen), so mic audio "captured just before the mute was detected but not yet sent" is never sent (FR-014). It delays every line by 0.5 s, far inside 001's SC-002 budget. Frames keep their capture time, so word timings stay meeting-accurate. The only assumption about 001's API is "a per-frame gate on the mic input before mixing"; if it offers no hold, task T049 adds one delay line per input in front of the mixer.
- **Fail closed (design decision 34, 2026-10-08 — supersedes the fall-open below)**: on a Meet tab the gate never opens without a reading saying "unmuted". No first reading within `MUTE_INITIAL_WAIT_MS` (3 s), or a lost reading (after `MUTE_STALE_GRACE_MS` when last muted, at once when last unmuted, silencing from `now − MUTE_DETECT_SLACK_MS`), moves the gate to `unreadable`: the mic stays silenced and the panel shows "Not sent — can't see Meet's mute button". The next real reading returns it to `following`. The timers now only change what the panel says ("Checking…" → "can't see the mute button"), never what is sent. Non-Meet tabs (`unsupported`) are unchanged.
- (superseded by decision 34) **Start**: on a Meet tab the gate starts **closed** (mic silenced) until the first reading arrives, up to `MUTE_INITIAL_WAIT_MS` (3 s); then, with no reading, it opens and the mic shows "mute state unknown — mic is being sent" (US3-3, US3-4, FR-017).
- (superseded by decision 34) **Lost reading** (page reload, adapter detached): if the last known state was muted, stay closed for `MUTE_STALE_GRACE_MS` (5 s) while the page reconnects, then fall back to unknown (open). If it was unmuted, unknown opens at once.
- **Rapid toggling**: the latest reading wins; each reading applies from its own `observedAt`.
- **Latency**: closes within one frame of the reading arriving (the hold covers the detection window); reopens as soon as the unmute reading arrives, audible in the stream 0.5 s later — both under FR-015's 1 s.
- Non-Meet tabs: `mute` is unsupported, the gate is always open, status unchanged from 001.
- Muted time costs nothing extra: there is one billed session whatever the mute state. The earlier question about suspending a separate mic session is moot (decision 30).

**Alternatives considered**: dropping muted mic frames instead of silencing them (the mixer needs a frame per tick to keep the two inputs aligned); gating after mixing (the mic cannot be separated from the mix); no guard hold (leaves the detection window uncovered, contradicting FR-014's "including audio captured just before the mute was detected"); delaying only the mic (shifts the user's voice against everyone else's in the mix).

## R9. Labels: keys, renames, overrides, remembered names

**Decision**:
- Every segment has a **speaker key** derived from stored fields: `self` (attributed to Meet's self label), `caption:<normalised caption name>` (another caption name), `others` (fallback). Normalisation: NFC, trim, collapse whitespace, case-fold.
- A **rename** is meeting-level: `Meeting.speakerRenames[key] = { name, origin: 'manual' | 'remembered' }`. It applies to every segment with that key, past and future (FR-018). Renaming to a name another key already shows simply shows both under that name (US4-5) — no data is merged.
- An **override** is per segment: `TranscriptSegment.labelOverride` (a name) — wins over any rename and survives later renames (FR-019).
- The displayed label is computed, never stored over the original: `displayLabel(segment, meeting) = override ?? rename(key) ?? segment.speakerLabel`. Its source for styling: override → `manual`; otherwise (red-team 2026-10-08: `others` has no rename — it mixes the user's lines with everyone uncaptioned, so a rename of it is rejected by the protocol and runtime and ignored if stored; only single-line overrides correct an "Others" line) the segment's `labelSource` (US4-2, US4-3). One pure function in `src/core/transcript/labels.ts` that 003 (chat) and 004 (export) also use (FR-021).
- **Remembered names** (FR-022, decision 20): renaming a `caption:` key also writes `Settings.speakerNameMappings` (caption name → display name). Renaming it back to its caption name removes the mapping. When a meeting first sees a caption key that has a mapping and no rename of its own, it records `{ name, origin: 'remembered' }` in the meeting — so later edits in Settings change future meetings only, and stored meetings stay as they were. Renames of `self` are meeting-only (the user's name lives in settings); `others` cannot be renamed at all, and an override of an "Others" line is never remembered (red-team 2026-10-08).
- Storage: no IndexedDB version bump. New fields are added to records written from 002 on (`schemaVersion: 2`); readers normalise v1 records (`captionName: null`, `labelOverride: null`, `speakerRenames: {}`).

**Rationale**: keeps the raw attribution (what Meet said, or the fallback) intact under every correction, so a correction is reversible and the export (004) can still tell sources apart.

## R10. Relabel UI and message path

**Decision**: each transcript label is a button. Activating it opens a small dialog with the current name, a text field (with the meeting's names as suggestions), and two actions: **Rename everywhere** ("Rename 'Jane D.' on all its lines") and **Just this line**. A line with an override offers **Clear override**. Keyboard: Enter submits Rename, Escape cancels, focus returns to the label. Names: trimmed, 1–60 characters (same rule as the user's name).

Path: while the meeting runs, the panel sends `labels/rename` / `labels/override` over the existing `live` port to the offscreen document (the single DB writer during a meeting), which stores the change, updates its snapshot and broadcasts `live/labels` / `live/segment-updated`. When no meeting runs, the panel's `MeetingApi` writes through `MeetingRepo` directly (the same path 001's Delete uses). Remembered-name writes go through `SettingsStore` from the panel in both cases.

Settings gains a **Remembered names** section: list of caption name → display name, edit display name, remove.

## R13. Real Meet DOM, inspected 2026-10-08 (findings)

The user's first real call with the built extension (a solo test call, page inspected live through Claude in Chrome) showed transcription working, speaker names never working, and Meet's notification area hidden, so the user could not admit a participant. What the real in-call page has, and what it changed:

- **Regions, in DOM order**: `div[role=region][aria-label="Call feature notifications and actions"]` (25 children; child 3 is a participant chip `div.CvJr8b` holding an avatar `img` and spans), then `div[role=region][aria-label="Captions"][tabindex=0]` (`vNKgIf UDinHf`, parent `div.iOzk7[jsname=dsyhDe]` with one child), then `div[role=region][aria-label="Call controls"]`.
- **Root cause of both failures**: `captionsRegion()` took the first region with any child that had an avatar and a span, which was the notifications region (the chip matched). The caption observer then watched the wrong region, so no turn was ever seen, and `hide()` tagged that region's parent, hiding the notifications and admit area.
- **Caption turns** (confirms D3): region > `div.nMcdL.bj4p3b.gBdnfe.UVSzeb` per turn > [`div.adE6rb` > (`img.Z6byG.r6DyN[data-iml]`, `div.KcIKyf.jxFHg` > `span.NWpY1d` = name)], [`div.ygicle.VbkSUe` = text]. After the turns: a `div` > `div.GvZY2`, and `div.IMKgW` with the "Jump to most recent captions" button. The local user's turns read "You" (confirms the English self word).
- **Mic and camera**: both are `button[data-is-muted]` ("Turn off microphone" `false`, "Turn on camera" `true`); neither has `data-mute-button`. The mic icon was not recorded.
- **Captions button**: no `aria-pressed`; label "Turn off captions" while on (presumably "Turn on captions" while off); icon `closed_caption` while on. The off icon was not seen, so the icon is not trusted for the state. No `[data-meeting-title]` on the page (the title comes from `<title>`, tier 3).

**Decision** (tasks T085–T088):
- A caption turn is a child whose first child (the header) holds the avatar and a span, followed by the text element; a chip (avatar and spans side by side) is not one. The captions region is the region with a turn and at most 3 other children (tier 1), else the region labelled exactly "Captions" (tier 3), else a focusable `tabindex=0` region with at most 3 non-turn children (tier 4). A region whose label mentions "notification" is never a candidate.
- `hide()` tags the captions region itself, never its parent or anything else (a blank band may remain where the captions were; noted for the manual check).
- `captionsOn` reads `aria-pressed`, then the English label, then the icon.
- `micButton` never returns a button whose label mentions "camera" or whose icon is `videocam*`; among `button[data-is-muted]` it takes `data-mute-button`, then a mic icon, then a label mentioning "microphone".
- Fixtures `tests/fixtures/meet/real-dom-captions-on.html` and `real-dom-captions-off.html` rebuild this structure with fictional names (the off state, the off icon and the mic icon are guesses, marked in the fixture). They join the synthetic snapshots until the user's anonymised snapshots arrive (T068/T069).

- **R4 result, real call 2026-10-10:** the collapse (zero-height band) stopped caption updates reaching the adapter ("No captions seen for a while") and did not free the space — Meet reserves it in its own stage layout while captions are on. Reverted to opacity-only hiding. Any further attempt starts from a live-DOM investigation of what reserves the space.
- **R4 closed, live call 2026-10-12 (design decision 61, tasks T128–T142):** the investigation was done by the user in a 5-person call. The stage is `main.axUSnc` with inline `inset: 64px 16px 304px` (304 = 80 control bar + 216 band + 8). The band is `div.fJsklc.nulMpf.Didmac.G03iKb.hLkVuf` (`data-side="3"`, inline `bottom: 80px`); it holds a caption settings row and the `div[role=region][aria-label="Captions"]` region that carries `data-live-assist-hidden`. Setting the stage's bottom inset to 88px sticks on the element, but the tiles keep their height, also after a window resize makes Meet lay out again: Meet sizes tiles from its own model of the window minus its docks, not from the stage element. With the collapse (above) that is two dead ends, so the band is accepted and nothing in the adapter touches the band or the stage.
  - **Decision**: a setting `showMeetCaptions` (off by default) decides whether `CaptionsControl` hides. Hidden stays exactly R4's opacity rule (`HIDE_CSS`, the `data-live-assist-hidden` tag on the region, the one stylesheet). Shown means the control adds nothing to the page: no tag, no stylesheet. `CaptionsControl.setShown(show)` can be called at any time, before or after `enable()`: turning it on removes the tag and the stylesheet at once; turning it off hides at once when captions are on, otherwise when they come on. It changes no phase, clicks nothing and reports no state, so the captions state, the watchdog and `wasOn` (what `restore()` puts back) are untouched; the caption observer is a `MutationObserver` on the region and does not depend on its style, so activity is not interrupted. `restore()` is unchanged (removing a tag and a stylesheet that are not there is a no-op).
  - **How the page learns the value**: from the service worker, on the existing one-shot channel to the content script (contracts/meet-bridge.md "Attach"): `meet/attach` and the `meet/ready` reply carry `showCaptions`, and `chrome.storage.onChanged` in the service worker sends `meet/show-captions { show }` to the running meeting's Meet tab when the stored value changes. The value is on the page before the port opens, so before `meet/enable-captions` can arrive.
  - **Alternatives considered**: (a) the content script reads `chrome.storage.local` itself — fewer messages, but the Meet content script would then read the store that also holds the keys and would act on something other than validated bridge messages; rejected (Principles I and V). (b) through the offscreen document (`offscreen/begin` plus a new internal message, a new method on the `PlatformAdapter` captions capability) — touches the protocol, the host, the runtime, both adapters and the contract suite for a value core never uses; rejected (Principle VI). (c) restart the captions flow on a change — would click nothing but would re-report `starting` and could reset `wasOn`; rejected (FR-029).
  - **Not done**: no change to the band, the stage or Meet's caption settings row; the row was not hidden before and is not now.
